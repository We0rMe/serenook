# Serenook

一个安静、简洁的 Windows 工作台。它将应用入口、清单、日记与随手记收在一处，让打开下一件事、记下下一件事与留住此刻都更轻一些。

## 当前范围

- 添加、修改和移除本地应用、常用文档、文件夹或在线网址入口
- 从 Windows 已安装应用中搜索、勾选并批量导入，新增入口统一进入睡眠区
- 本地入口找不到目标时可直接重新定位，保留名称、排序、作息及任务关联
- 常用入口进入编辑后支持在苏醒区或睡眠区内拖动卡片排序
- 常用入口、清单、日记与随手记组成四个可折叠工作区，可通过左侧把手实时拖动排序
- 随手记保留一页纯文本，无需标题；停笔、离开或关闭前自动保存，并纳入本地备份。恢复不含随手记的旧备份时保留当前页
- 随手记选中文字后右键“加入清单”，可修改并添加为一个任务；原文保留，已收存清单不参与添加
- 创建多张四列等宽清单，支持清单卡片与任务分别拖动排序、任务修改、星形完成状态、删除与每日状态重置
- 记录带标题与正文的日记，以只读大页浏览，支持修改或移除，并保留创建时间和最近修改时间
- 日记自动保留独立草稿，支持按月浏览、前后翻阅及 Markdown / 纯文本导出
- 左上角查找或 `Ctrl+K` 可查找入口、任务、日记与随手记，并定位匹配内容
- 随手记在本机记住阅读与光标位置，不抢占启动焦点；位置记忆不写入内容文件，也不触发备份
- 点击清单名称可展开阅读与编辑，已完成任务可按需收起，任务可关联一个已有入口
- 清单支持收存、查看与恢复；收存期间暂停每日重置，并保留任务状态、关联入口和原有排序
- 移除入口、任务、清单或日记后提供短暂撤销；本地保存使用完整替换，并保留最近 7 份自动备份
- 设置支持导出、预览和恢复本地备份，恢复前保留原记录，恢复中断后回退到完整的原记录
- 普通备份在记录实际变化前建立，至少间隔一小时；内容未变时不重复保存或新增相同备份
- 普通日期按星期与时段显示问候语；主流节日则在早晨、午后与夜晚显示对应的节日问候
- 自动读取 Windows 应用自身图标，并在本地提取轮廓生成简笔线稿
- 在线网址统一使用本机 Microsoft Edge 的线稿图标与低对比度标记
- 以 650 毫秒间隔依次启动当前工作台中的全部入口，避免瞬间并发
- 每 10 秒按完整路径轻量检测本地 `.exe` 运行状态，已运行应用不再重复启动
- 首次运行状态检测期间锁定“全开”，关闭工作台后不保留后台检测
- 可将暂时不用的应用移入默认折叠的睡眠区，并随时苏醒
- 新增入口可通过独立睡眠开关决定保存到打开区或睡眠区
- 右下角日签从 527 条安静短句中按日期顺序轮换，每日一签
- 左侧设置栏支持一键睡眠与一键苏醒
- 纪念日支持 1–7 个英文字母的自定义名称；设置后会在新芽书下方写下名称与累计天数
- 全新安装首次运行时柔和邀请用户阅读使用说明，已有旧版设置的用户不会重复看到
- 设置中提供安静简洁的使用说明与开机自启开关
- 睡眠区和设置项带有柔和的展开、收起动效
- 页脚书本、新芽与手写名称会在启动时缓慢自动绘制
- 自定义标题栏支持最小化、最大化/还原与关闭窗口
- 支持常见应用、Office / WPS / OpenDocument 文档、PDF、电子书、本地文件夹以及 `http://`、`https://` 网址
- 将入口、清单、日记、随手记与工作区偏好保存在 Windows 当前用户的应用配置目录
- 初次沿用系统外观，并可在设置中切换、记忆浅色或深色模式
- 启动后轻量检查 GitHub Releases，以设置按钮上的小点提示新版本；设置底部可主动检查、重试或查看说明并安装
- 不包含账号、云同步、最近记录或应用内控制

## 资源占用

以下数据来自 Windows 本机对本轮发布构建的静置采样，实际数值会因 Windows、Microsoft Edge WebView2 版本、已导入入口数量和页面状态而变化：

- Serenook 主进程静置工作集约 `28–31 MB`，私有内存约 `8–9 MB`。
- 将 WebView2 子进程全部计入时，本次启动峰值工作集约 `366 MB`，私有内存约 `224 MB`。
- 本次采样共包含 1 个 Serenook 主进程与 6 个 WebView2 子进程；关闭 Serenook 两秒后，相关 WebView2 子进程为 0。
- 当前安装包约 `3.1 MB`，主程序约 `12.7 MB`；应用运行依赖 Windows 已安装的 Microsoft Edge WebView2 Runtime。
- 日常运行建议预留约 `500 MB` 可用内存。批量打开的其他应用不属于 Serenook 自身占用，并会以 650 毫秒间隔依次启动。

这里的“峰值”是作者本地实验的实测峰值，但并不覆盖所有机器的硬性上限。

## 开发环境

项目使用 Tauri 2、TypeScript 和 Vite。仓库中的脚本不包含开发者用户名或固定工具目录；需要将 `cargo`、`pnpm` 与 Node.js 放入 `PATH`。如需让依赖与编译缓存避开系统盘，可在本机自行设置 `CARGO_HOME`、`RUSTUP_HOME`、`CARGO_TARGET_DIR` 和 pnpm store。然后运行：

```powershell
.\scripts\dev.ps1
.\scripts\build.ps1
```
